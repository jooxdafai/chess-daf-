## Traces and effective guards
- Existing before-request guard enforces exact Origin, JSON object/16KiB body, cookie-derived owner and guest-profile cap before the new API. Library paths accept only existing catalog IDs; level 1–5, page 0–99 and twenty results per page are bounded. Guessed IDs expose public puzzle positions, not another browser's progress.
- Progress uses a composite owner/puzzle key, bound SQL values and the existing BEGIN IMMEDIATE transaction. Every read/write includes the guard-derived owner; no request can choose that owner. Legal move, exact integer stored ply and solved checks precede updates, so stale/concurrent submissions cannot advance twice. Wrong/assisted/solved counts are server state rather than client claims. Alternate immediate mates retain the actual final board. The additive table does not touch existing games/reviews/personal exercises.
- Immutable ~2MB dataset lives outside web/static, loaded from a fixed project path and cached once per process. All 10,000 positions/complete solutions were validated legally; max 15 solution plies. No runtime download, engine spawn, client-selected file or code execution is introduced. Progress is sparse and bounded by 10,000 known IDs per existing guest; listing scans at most that owner's 10,000 records and builds only twenty boards. Existing nginx request/resource limits remain; no new model/API credentials.
- The build-only importer fetches a fixed official HTTPS URL, parses CSV as data, validates legal boards/moves, stops at 10,000 unique positions and writes known local paths. zstandard was installed only in disposable tooling, not production requirements. The committed manifest records CC0 provenance, selection limits and checksum; later upstream ratings/order may differ.
- Text is constructed with DOM textContent, never innerHTML. Arrows derive numeric coordinates from server-selected legal UCI; colors and SVG attributes are fixed. Hint/solution requests deliberately disclose the public answer while marking assistance; read lists omit solutions. No competitive secrecy/anti-cheat promise is made.
- Browser busy guards gate editing/navigation during requests and frame display; server checks remain authoritative. Displaying solution frames cannot submit moves or count a success. Reviewing after a completed unassisted solve preserves credit. Existing app CSP/cookies, dependency pins, read-only CI token/pinned actions and service configuration stay intact.

## Limits
Scoped review, not project-wide or dependency-advisory clearance. Feedback uses verified move facts plus source tactical themes and the stored solution, not deep fresh refutation of every legal alternative. Only immediate alternative mates are automatically accepted. Puzzle ratings are not player Elo; the frozen filtered subset is not statistically representative. Chrome input/geometry is not all-browser/physical-device certification. Existing intermittent native-engine503 behavior is unchanged; library solving itself needs no native engine. Rollback can point to the previous app; retain the additive table and newer data rather than restoring over them.
