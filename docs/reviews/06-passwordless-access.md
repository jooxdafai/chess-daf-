Owner explicitly requested standalone access without a password; removal of the Joo Flow gate is intentional.

No confirmed feature-related vulnerabilities remain in this reviewed scope. Merely removing the old gate would expose the shared owner's history. The implemented change instead uses random 256-bit HttpOnly browser cookies, stores only SHA-256-derived owner identifiers and adds bound owner predicates to every affected resource/query. Public requests ignore legacy X-Chess-User; the proxy clears it and forwards only this app's cookie. Game lookups enforce owner before reads, mutations, cached reviews, engine work and exports. Exercise primary keys are namespaced; progress/review joins are owner-filtered. Existing rows migrate atomically to the legacy owner and are never reassigned to an anonymous visitor. No credential/user input selects an executable or database path.

Cookie policy: host-only, Secure under the canonical HTTPS origin, HttpOnly, SameSite=Lax, app-scoped path and one-year browser persistence. POST still requires exact configured Origin and JSON; responses are no-store + Vary: Cookie. The browser token is a bearer capability; copying it shares that space. There is no account recovery or cross-device identity. Other apps share the hosting origin; browser isolation here is between anonymous browser profiles, not a claim of origin isolation from all first-party apps.

Public request/write limits reuse the existing per-IP nginx zones. Existing one-engine-at-a-time lock, fixed native executable, CPU/memory/task limits, 600-ply/2,000-game global bounds remain. Guest metadata is bounded to 1,000 profiles; reaching capacity returns 429 for new profiles without blocking existing ones. Capacity/abuse monitoring is still an operational concern for an anonymous public service; this review makes no availability guarantee.
