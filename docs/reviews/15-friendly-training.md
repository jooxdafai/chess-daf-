## Traced boundaries

- `/api/games` permits only the existing settings keys; `GameStore.create` validates integer difficulty 1–5 and the existing time/mode/color choices. Only the default level changes. A caller cannot provide a FEN, executable, heuristic, seed or sleep duration. No schema, identity, cookie, dependency or deployment-configuration change.
- `/bot` loads an owned game before selecting a move. The original turn/result checks remain; the final `store.move` re-reads ownership and rejects stale ply, incorrect actor, expired clock or illegal moves under the SQLite transaction. Concurrent requests cannot commit two replies for one ply. The simplified policy consumes only the server-reconstructed board and validated level, enumerates its legal moves once and scores one copied position per candidate. It adds no recursive search, external request or interpreter sink.
- `Engine.slot` preserves nonblocking single-job exclusion and trusted deployment-path existence checks, with release in `finally`. Both easy opponents and native sessions use it. Native process creation still receives a fixed argument array from the trusted server environment, Threads=1, Hash=16 and bounded searches. Easy moves never start a native process; hints/reviews retain the native session path and original budgets.
- Pacing is a bounded browser timer before `/bot`, outside server workers/engine locks. It is driven by validated server settings, reduced under clock pressure, and leaves server clocks authoritative. Existing UI busy guards prevent new-game/resign/sync/history actions while the request cycle runs; premove editing stays available. The existing server ply/turn checks remain the defense against stale/concurrent clients. A caller can bypass UI pacing; it grants no additional access or move authority, and this solo trainer makes no competitive clock/anti-cheat claim.
- Opponent/help/status strings use `textContent`, with fixed labels and no HTML sink. PGN changes only a fixed opponent string after the existing owned-game read; ID/filename and serialization remain unchanged. The random choice is for fallibility, not authentication or cryptographic ownership. No Elo or calibrated human-strength claim is made.
- CI adds local syntax/unit commands under the existing read-only token and pinned actions. Test-only seed routes remain registered solely in the standalone loopback fixture entry point, absent from production.
