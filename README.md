# Chess DAF ♞
Standalone, passwordless Arabic chess and learning at a Joo Flow URL. Each feature ships in a separate, reviewed pull request. PRs are stacked; deployment can use the tested final head before the stack is merged.

## Local development
Requires Python 3.12+. `uv venv && uv pip install -r requirements.txt pytest`; run `.venv/bin/python -m pytest -q`.

Run `CHESS_PUBLIC=1 CHESS_COOKIE_PATH=/ CHESS_ORIGIN=http://127.0.0.1:18971 .venv/bin/gunicorn 'backend.app:create_app()' --bind 127.0.0.1:18971 --workers 1 --threads 4`. No password or identity header is needed. Production must keep the backend loopback-only. POST requires JSON and the exact configured Origin. The old proxy-authenticated mode remains opt-in for legacy/internal tests when CHESS_PUBLIC is unset.

## Foundation
SQLite stores complete games and SAN/UCI moves. python-chess enforces legal moves, promotions, en passant, castling and game termination. Stale writes are rejected transactionally. Responsive RTL UI supports tap-to-move and all promotion choices. The foundation PR is a local two-sided board; engine/clock controls become active in the next PR.

## Security and licensing
Public access uses a random, HttpOnly browser cookie. Only its SHA-256-derived owner identifier is stored; games, reviews, exercises and progress are scoped server-side to that browser. The proxy forwards only this app cookie and clears legacy identity headers. Cookies are Secure on HTTPS, host-only and scoped to the app path. No credentials are checked into this repository. Clearing browser data or changing devices starts a new space; there is no account recovery or cross-device sync. Old shared-owner records remain preserved but are not handed to anonymous visitors. See `docs/reviews/` for scoped Marja reviews. GPL-3.0-or-later; chess rules and SVG piece designs come from [python-chess](https://github.com/niklasf/python-chess), © Niklas Fiekas and contributors. The pieces originate from Colin M. L. Burnett's chess set, distributed with python-chess under GPL. Stockfish integration is a separate UCI executable, never a browser download.

## Engine and clocks
Install distribution Stockfish (`apt-get install stockfish` on Ubuntu) or set `STOCKFISH_PATH` to a trusted binary. Native integration tests run when it exists. Levels 1–2 are simplified practice opponents: they score legal moves one ply ahead using material, basic development and immediate exposure, then sometimes choose a different legal move (35% / 10%). They have no reply search and are deliberately fallible, without a calibrated Elo or human-strength claim. Levels 3–5 use Stockfish Skill Level 8/14/20 with the existing 120/300/300ms search budgets. Hints and completed-game reviews always use native Stockfish, including on easy levels. One worker with four threads is required for the shared job lock. Times: unlimited, 1, 3 and 10 minutes, without increment. Server time counts while disconnected, including engine thinking. Hints only in training on your turn. Safety limits: 600 half-moves, 2,000 saved games globally and 1,000 guest profiles; history shows the current browser's latest 100. The nginx route applies existing per-IP request/write limits; engine concurrency/resource caps remain enforced. Existing games remain saved when starting another.

New games default to **مبتدئ مريح**, training mode and no clock. The interface calls levels 1–2 **خصم تدريب**, and PGN exports label them `Practice opponent`. Existing games retain their saved settings; changing the difficulty menu applies to the next new game. Levels 1–2 wait before requesting the bot move: about 1.2s untimed/10-minute, 0.9s in 3-minute and 0.6s in bullet, less time already elapsed since receiving the position. This target shrinks near flag fall. Premoves remain available during this wait. The wait holds no server worker or engine lock and counts against the opponent's running server clock, rather than waiting after its move and charging the human. Network latency still counts normally. This is UI pacing, bypassable by a direct API caller, not a competitive anti-cheat mechanism. Stronger levels keep their previous response timing.

Run `node --test tests/training-view-unit.mjs` and the Python suite for difficulty defaults, legal/fallible selection, terminal positions, clock accounting and honest PGN names. With the public loopback fixture and Playwright tooling variable below, `node tests/friendly.mjs` checks default settings, measured untimed pacing, opponent status and manual difficulty changes. It also supports the public live URL.

## Arabic review
A completed game is analysed automatically in the UI, with retry and cached results. Every half-move gets a best alternative, legal continuation, Arabic lesson and centipawn loss from the mover's perspective. The score `/100` is our simple average `100*exp(-loss/300)`, not Chess.com's accuracy or an Elo rating. Quick searches may change their recommendation at greater depth. PGN can be exported without changing the game. No paid language model is required; explanations state verified chess facts with deterministic Arabic templates.

## Premove

The playing board keeps its 64 buttons and reuses piece images. Click/opponent moves use a short 110ms transform animation (disabled by reduced-motion preference); drag releases remain at the destination immediately while the server confirms the move. Rejected requests restore the confirmed board. This is a visual projection only: server legality, ownership and clocks are unchanged. Queue controls reserve a stable row so showing them does not resize the board. `tests/smooth.mjs` covers stable nodes, delayed replies, rejected drag rollback, real intermediate animation position and reduced motion; `tests/board-view-unit.mjs` covers capture, castling, en passant and promotion projection. No universal frame-rate guarantee is implied.

While waiting for the opponent, tap or drag your pieces to append up to **8 premoves**. The purple numbered squares and horizontally scrollable list show their order. Pieces appear at their projected future squares so the same piece can be queued again from there. This is a conditional preview, not a prediction of the opponent's moves. Undo the last queued move or cancel all with the buttons; Escape/right-click cancel all. A submitted move is already in flight and cannot be undone by queue controls.

Each head executes only after the next opponent reply, with matching game/ply/turn and current server legality. If one becomes illegal or its piece is captured, it and all later moves are discarded. Finished games, connection errors, reload and manual sync clear the queue. All four promotion choices are available; game termination after promotion also clears the tail. Server clocks, network time and authoritative rules remain unchanged; there is no zero-time guarantee.

Run `node --test tests/premove-unit.mjs`. For browser coverage, start `.venv/bin/python tests/premove_server.py /tmp/unique-premove.sqlite`, then use the same `CHESS_PLAYWRIGHT_MODULE` variable with `node tests/premove.mjs`. The loopback-only fixture adds scripted capture, promotion and checkmate positions inside its executable entry point; these routes are never registered by the production app. `CHESS_PREMOVE_LIVE=1 CHESS_TEST_URL=https://jooflow.space/chess-daf/` runs the common browser scenarios with the production opponent policies, skipping fixture-specific positions.

Multi-queue regression: run `node tests/multi-premove.mjs` with the same fixture/tooling variable. It checks dependent same-piece order, undo/all, invalid-middle stop, cap/numbering/layout, reload, Chrome touch input and terminal promotion/mate. `CHESS_MULTI_LIVE=1 CHESS_TEST_URL=https://jooflow.space/chess-daf/` checks two quiet queued moves with the production opponent policies, rather than requiring a particular tactical reply.

## Drag pieces
On the playing board, hold and drag your piece with the mouse or one finger, then release on its destination. The piece follows your pointer and valid destinations are highlighted. Click-to-move and keyboard button activation remain available. Dragging during the opponent request queues a premove; promotion opens the existing four-piece chooser. An illegal/outside drop, Escape, pointer cancellation, lost capture/focus, board flip or a server position update cancels the drag. Touch dragging is confined to the board; scroll the page from outside it. Puzzle boards keep their existing tap controls.

With the isolated premove fixture running, use the same Playwright tooling variable with `node tests/drag.mjs`. It exercises actual mouse input and Chrome-emulated touch, one-minute play, exactly-once submission, legacy clicks/keyboard, invalid drops, cancellation, board flip, both colors, reply-during-drag, premoves and seeded underpromotion. `CHESS_DRAG_LIVE=1 CHESS_TEST_URL=https://jooflow.space/chess-daf/` runs common scenarios against native Stockfish, skipping the local promotion seed. Emulated touch is not a physical iOS/Android-device certification.

## Personal training
Three starter puzzles plus up to five exercises from your biggest inaccuracies per reviewed game. Your attempts, solved status and use of hints survive reload/restart. Personal exercises ask for the stored engine recommendation, not a claim that no alternative move is good. Progress shows recent 12 reviewed-game scores and weak concepts; it is not an official rating.

## On-board review player
Finished-game reviews show an amber played-move arrow and green engine alternative, square highlights and an animated Arabic caption on the board. Equal choices use one green arrow. Choose **قارن / اللي اتلعب / البديل**, then play/pause, restart or step through the selected explanation. Previous/next navigate the game's moves; both counters stay LTR inside the Arabic UI. Captions prefer empty, unhighlighted space and use a compact layout on short boards; full explanations remain in the coach panel. Playback pauses on navigation, mode/board-orientation changes, leaving the tab/focus or starting another game; automatic arrow/text animation respects reduced motion.

The backend supplies a legal played frame and up to five legal continuation frames, including SAN/UCI, before/after FEN and a move-specific explanation. Replay changes presentation only, without `/move` calls, saved-game or clock changes. Older cached text reviews gain `visual_version: 1` frames from their legal SAN prefix on the owned review request, preserving scores without another engine job or SQL schema migration. Unavailable/invalid alternatives are not animated. Quick engine variations remain approximate choices, not forced outcomes.

Use `node --test tests/review-view-unit.mjs`; with the existing public isolated fixture and Playwright tooling variable, run `node tests/board-review.mjs`. The same browser suite supports `CHESS_TEST_URL=https://jooflow.space/chess-daf/` for production-opponent/native-analysis verification. Python review tests cover cache upgrades, legal-prefix truncation, castling, en passant and underpromotion. Chrome geometry/reduced-motion coverage is not a physical-device or all-browser certification.

Browser verification: install `@playwright/test` in a disposable tooling directory. Run `.venv/bin/python tests/ui_server.py /tmp/unique-chess-test.sqlite`, then `CHESS_PLAYWRIGHT_MODULE=/absolute/path/to/@playwright/test/index.mjs node tests/browser.mjs` (Google Chrome installed). This uses a scripted test engine and separate SQLite database; production never imports it. Use a fresh disposable DB each run. The Python suite includes a separate native Stockfish integration test.

## 10,000-puzzle library
The training tab includes a frozen [Lichess open database](https://database.lichess.org/#puzzles) subset under CC0-1.0, separate from existing starter/personal exercises. Exactly 2,000 distinct positions per level: ratings <1000, 1000–1399, 1400–1799, 1800–2199, >=2200. These are puzzle ratings, not player Elo. Popularity >=80, >=100 plays, at most 15 solution plies. `assets/puzzles.manifest.json` records source, selection and SHA256. `scripts/import_puzzles.py` rebuilds a subset from the changing official stream (tooling-only zstandard, no new production dependency); the committed snapshot is reproducible by its checksum, not a promise that a later download has identical ratings/order.

Every solution is legality-checked, including applying the opponent's first setup move before displaying the position. Play all your solution moves, with automatic opponent replies; any legal immediate checkmate is accepted, including alternatives. Other alternatives are described as outside the stored solution, not declared objectively losing by a shallow engine. Feedback compares legal move facts and Arabic tactical theme guidance, with a step-by-step solution on the board; it is deterministic teaching, not bespoke deep analysis of every wrong line. Three hint stages reveal the idea, source square, then move arrow. Hints, revealed alternatives after a wrong answer and opening the solution before completion mark assistance. Reviewing after an unassisted success preserves that credit. Revealing alone never marks solved.

The shared dataset is outside the static web root and loaded once per process. Lists return 20 positions per page without answers. A new additive `library_progress` table stores only attempted/hinted puzzles per anonymous owner; existing games, personal exercises and their counters remain intact. Counts for the library are displayed separately. Transactions enforce stored ply/legality and prevent duplicate submissions. Reload resumes the current puzzle position. Browser storage/cookie limits remain as documented above. No runtime download or additional native search is needed.

Verification: Python tests validate all 10,000 unique positions/complete solutions, level totals, hint progression, multi-step solving, stale input, CSRF, independent owners and assistance accounting. With the loopback fixture running, use the existing Playwright tooling variable with `node tests/library.mjs` for wrong/correct feedback, actual drag, resumed position, solve/solution frames, levels and mobile geometry. It also accepts CHESS_TEST_URL for live verification.
